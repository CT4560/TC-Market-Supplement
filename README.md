# Market Board Collector

FFXIV 繁中服的 Dalamud 外掛。當你**自己**在遊戲裡打開市場板查看物品時，把 Universalis 沒有資料的物品（主要是繁中服的舊染劑／色素）的掛單與成交紀錄，回報給社群伺服器。

這個外掛是「社群回報」專案的一部分：繁中服有一批舊染劑在 Universalis 完全沒有價格資料，只能靠玩家用外掛回報，做法跟 Universalis 自己的上傳器一樣——**公開、匿名，不需要任何金鑰或帳號**。伺服器端（接收 `/community/upload`、提供 `/community/items`、自己的資料庫）在 [`server/`](server/README.md)，跟外掛放在同一個專案、各自獨立建置。

## 外掛做什麼

- 你在市場板點進某個物品時，遊戲會把該物品的掛單與最近的成交紀錄傳給你的客戶端。外掛只是**被動收下這些封包**。
- 遊戲把掛單分成多個封包傳送（每包最多 10 筆），最後一個封包沒有結束標記，所以外掛在該物品「安靜 2 秒」後，才把這次掃描視為結束、合併成一筆回報。
- 沒有人在賣的物品，遊戲不會傳掛單封包，只有成交紀錄；這種情況外掛回報「目前沒有掛單」。
- 外掛會先向伺服器詢問「哪些物品要收」（`GET /community/items`），**只回報清單內的物品**；Universalis 已經有資料的物品不會回報。清單約每 30 分鐘更新一次。
- 外掛**預設會自動**把掃描結果送到固定的官方社群伺服器（`POST /community/upload`），不需要金鑰、也不需要自己填網址；不想回報的人可以在設定視窗關掉「啟用上傳」。

**外掛完全不會操作遊戲**：不模擬按鍵、不自動翻市場板、不自動掃描。要掃哪些物品、掃多快，都是你自己在遊戲裡點的。

## 隱私

會上傳的資料，僅限市場板上的物品資料：

- 你目前所在的世界編號、物品編號、掃描時間
- 每筆掛單：單價、數量、是否 HQ、**雇員名稱**（市場板上本來就公開顯示）、遊戲給的掛單編號
- 每筆成交紀錄：單價、數量、是否 HQ、成交時間、**買家名稱**（市場板的成交紀錄上本來就公開顯示）

**不會**上傳：你自己的角色名稱、角色編號、背包內容、位置，或任何其他遊戲資料。買家名稱與雇員名稱是別的玩家的角色名稱，只因為它們本來就公開顯示在市場板上才會回報。

另外，如果打開「寫入本機檔案」，外掛會在你電腦上的設定資料夾寫 `capture.jsonl`（每次掃描的摘要：世界、物品編號與名稱、掛單與成交筆數）。這個檔案只留在本機，超過 5 MB 會輪替成 `.old`。

上傳是匿名的：沒有金鑰、沒有帳號，伺服器只會依來源 IP 做流量限制。安裝後預設就會回報，要停用請在 `/mbcollector` 關掉「啟用上傳」。

## 設定

安裝後，在遊戲裡輸入 `/mbcollector` 開關設定視窗（也可以從外掛安裝器的設定按鈕開啟）。

- **啟用上傳**：是否把掃描結果回報給社群伺服器。**預設開啟**；關閉就只寫本機檔案，不會送出任何東西。
- **寫入本機檔案**：是否同時寫 `capture.jsonl`（除錯用），預設開啟。
- 按「儲存」後立刻生效，不需要重開遊戲。
- 「測試連線並更新物品清單」按鈕會向伺服器要一次物品清單，方便確認連線正常；它只發一個 HTTP 請求，不會碰遊戲。
- 伺服器網址是寫死在外掛裡的，一般玩家不能也不需要設定。

狀態區會顯示：是否已啟用上傳、物品清單的更新時間與數量、本次遊戲階段上傳成功／失敗的筆數、最近一次上傳與取清單的結果。

設定檔是外掛設定資料夾裡的 `config.json`。台灣服啟動器的位置是 `%APPDATA%\FFXIVSimpleLauncher\Dalamud\Config\pluginConfigs\MarketBoardCollector\`（`capture.jsonl` 也在同一個資料夾）。格式如下，欄位可以手動編輯，但手動修改後要重新載入外掛才會讀到：

```json
{
  "UploadEnabled": true,
  "CaptureToFile": true
}
```

## 掃描的小提醒

- 掃描太快會被遊戲伺服器限流（日誌會出現 `Client is currently rate limited`），請放慢，一個物品點完稍等一下再點下一個。
- 伺服器對每個來源 IP 也有上傳頻率上限（每秒最多 4 次）；手動點市場板不可能碰到這個上限。
- 外掛只讀你目前所在的世界；要回報其他世界，請到該世界的市場板掃描。

## 建置與打包

需求：

- 台灣服啟動器自帶的 Dalamud（API 13、.NET 9）。專案使用 `Dalamud.NET.Sdk/13.1.0`，建置時必須讓環境變數 `DALAMUD_HOME` 指向台灣服 Dalamud 的 `Injector` 資料夾（不是國際版 XIVLauncher 的那套）。
- .NET 10 SDK（Dalamud.NET.Sdk 需要）。

手動建置（PowerShell）：

```powershell
$env:DALAMUD_HOME = 'C:\Users\<你>\AppData\Roaming\FFXIVSimpleLauncher\Dalamud\Injector\'
dotnet build -c Release
```

輸出在 `bin\Release\`。開發時可在遊戲裡 `/xlsettings` → 實驗 → 開發外掛位置，加入 `bin\Release\MarketBoardCollector.dll`。**遊戲執行中請不要重新建置到 `bin\Release`**（會鎖檔或影響正在執行的外掛）。

打包成可安裝的 zip：

```powershell
powershell -NoProfile -File .\pack.ps1
```

`pack.ps1` 會用台灣服 Dalamud 建置 Release，輸出到 `dist\build`（不動 `bin\Release`），再把 Dalamud SDK 內建的 DalamudPackager 產生的 `latest.zip` 複製到 `dist\latest.zip`，並列出內容、大小與 SHA256。腳本開頭的兩個參數 `-DalamudHome`、`-DotnetRoot` 可以覆蓋預設路徑。`dist\` 已在 `.gitignore`。

`repo.json` 是 Dalamud 自訂儲存庫的範本，所有下載連結都是佔位字串（`REPLACE_WITH_DOWNLOAD_URL` 等）。要發佈時才需要：把 `latest.zip` 放到某個可下載的位置，填入連結，並讓 `AssemblyVersion` 與這次打包的版本一致（`pack.ps1` 會在不一致時警告）、更新 `LastUpdate`（Unix 秒）。**這個專案目前沒有發佈到任何地方。**

## 已知限制

- **拿不到每筆掛單真正的上架時間**。Dalamud 的 `LastReviewTime` 不可信（只是物件建立時間，封包解析根本沒賦值），所以外掛不送這個欄位；伺服器用「第一次看到這筆掛單（以掛單編號比對）的時間」代替，「更新時間」只代表掃描當下。
- 沒人在賣時，遊戲完全不送掛單封包，外掛靠「有成交紀錄、卻沒有掛單封包」推論為無人販售；如果連成交紀錄都沒有（物品完全沒交易過），就不會有任何事件，該物品不會有回報。
- 伺服器對單次上傳有上限（掛單 100 筆、成交 50 筆）與資料檢查（單價與數量需為正整數）：外掛上傳前會先過濾掉單價或數量不合法（≤0）的個別項目、並把掛單截斷在 100 筆以內（正常情況幾乎不會觸發，只是保險），避免單一筆爛資料害整包被伺服器拒絕。收到 429（上傳太頻繁）後會暫停上傳 60 秒再自動恢復，不會立刻重送。
- 設定視窗（ImGui）目前只做過編譯驗證，還沒有在遊戲內實際操作過。
- 尚未做「完整掃描全部舊染劑」的實測（需要玩家在遊戲裡逐一點選市場板）。
- **上傳預設是開啟的**：不想回報的人要自己到 `/mbcollector` 關掉「啟用上傳」。
- 伺服器網址寫死在 `Plugin.cs` 的 `DefaultEndpoint`（`https://api-ffxiv-bot.epicurean-expedition.com`）。**用這個版本、沒設環境變數，而且「啟用上傳」開著（預設就是開）時，你掃描到的舊染劑資料會真的送到這個官方伺服器。**
- 開發者測試用：啟動遊戲前設定環境變數 `MBCOLLECTOR_ENDPOINT`（例如 `$env:MBCOLLECTOR_ENDPOINT = 'http://127.0.0.1:8787'`），外掛就改用這個網址（需要伺服器端設定 `COMMUNITY_UPLOAD_ENABLED=on`）。它不出現在設定視窗，一般玩家不需要也不會用到。
- 外掛沒有簽章，也沒有發佈到任何公開儲存庫；只適合自己與信任的人使用。
